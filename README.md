# Лампада

«Лампада» — Flutter-приложение для короткой ежедневной православной сессии:
одна единица контента на экран, без лент и дашбордов. Дневной материал приходит
с [Азбуки веры](https://azbyka.ru/).

## Что внутри

У дня три независимых трека:

- **сессия дня**: цитата, совет и притча в полноэкранном просмотрщике;
- **Евангелие дня**: стихи отдельными страницами общего просмотрщика
  карточек, с толкованием по кнопке у стиха. Последняя карточка предлагает
  прочитать полную главу в ридере «Библии» с первого стиха. Если отрывок
  захватывает несколько глав, можно выбрать любую из них;
- **«Основы веры»**: личный курс из 365 тем во вкладке **«Планы»**.

Во вкладке **«Библия»** доступны все 77 книг, которые перечислены в каталоге
«Азбуки веры», включая неканонические. Книга и глава выбираются из локального
каталога; чтение продолжается с последнего открытого стиха выбранной главы, загружаемой с
`azbyka.ru/biblia/` в русском Синодальном переводе. Свайп ведёт к
следующему стиху, затем к началу следующей главы и книги. Для стихов работают
закладки и отправка текста. Скачанные главы сохраняются для чтения без сети:
их плитки обведены рамкой. Приглушённая заливка слева направо показывает долю
главы до последнего открытого стиха включительно; позиция сохраняется отдельно
для каждой главы. После открытия последнего стиха главы отмечаются полной
акцентной заливкой, которая сохраняется и при повторном чтении. Первая загрузка главы требует интернета.

В открытой закладке стиха или толкования кнопка **«Открыть главу»** справа
в AppBar открывает главу на сохранённом стихе в существующем покарточном
просмотрщике Библии; для толкования — на первом стихе указанного отрывка.
Можно листать как назад, так и вперёд по главе. Кнопка доступна,
если книгу и главу можно определить по сохранённой ссылке, в том числе у
старых закладок. Чтение, кэш и отметка прочитанной главы работают так же,
как при открытии главы из вкладки «Библия».

Любой трек отмечает день прочитанным. В «Основах веры» тема и активность дня
засчитываются на отдельной карточке «Тема прочитана» после всех чанков текста.
Текст темы разбит по предложениям. Длинное предложение показывается
как превью до 150 символов с кнопкой полноэкранного чтения. Перенос строки
внутри предложения не создаёт новую карточку. Источник скрыт в карточках,
но сохраняется в тексте для отправки. Точки слева показывают прогресс внутри темы, включая
финальную карточку. Следующий свайп после карточки завершения открывает следующую
тему. Можно остановиться до завтра, следуя рекомендованному темпу. Прогресс курса — число явно завершённых тем, отдельно от открытой темы.
При возвращении курс открывает последнюю просмотренную карточку внутри темы,
включая финальную; после всех
365 тем показывает завершение и остаётся доступным для повторного чтения.
Старая позиция сохраняется без автоматического зачёта прошлых тем.
Место чтения (тема и страница) записывается вместе. Отметка завершения темы
и активность дня сохраняются двумя отдельными операциями: аварийное закрытие
между ними может оставить тему завершённой без отметки дня. Восстановление
страницы не засчитывает уже завершённую тему повторно в новый день.
Курс не зависит от выбранной календарной даты. При входе на «Домой» приложение
открывает первый непрочитанный дневной раздел; когда дневные материалы прочитаны —
показывает сам день. Во вкладке «Планы» нажатие на курс открывает его страницу с описанием,
источником, объёмом и личным прогрессом. Кнопка «Начать» / «Продолжить»
открывает читалку; после завершения курса доступно «Перечитать».
Возврат из читалки ведёт на страницу курса. Двойные галочки слева от заголовка
курса в «Планах» приглушены до завершения темы сегодня и становятся яркими
по тому же условию, по которому скрывается обёртка курса над navbar.
На чистой установке активного плана нет. Открытие списка и страницы курса
не начинает его: только кнопка «Начать» сохраняет первую позицию чтения.
После начала курса на всех четырёх вкладках над кнопками navbar, внутри общей стеклянной капсулы,
слева показывается «ОСНОВЫ ВЕРЫ №X/365» с номером текущей темы,
справа — число просмотренных карточек текущей темы, включая финальную. Полоска показывает прогресс текущей темы. После завершения одной темы
за сегодняшний день обёртка скрывается до следующего дня. Нажатие на эту
строку открывает читалку напрямую, без страницы описания; возврат ведёт
на ту вкладку, из которой начали чтение.

На «Домой» календарная полоска листается неделями свайпом через PageView.
Над ней всегда зарезервирована строка для названия седмицы: загрузка, ошибка
или отсутствие названия не сдвигают календарь и содержимое. Длинное название
сокращается многоточием, чтобы высота строки оставалась постоянной.
Просмотр другой недели не меняет материал: день выбирается нажатием на число.
Свайп по содержимому переключает дни и синхронизирует полоску с выбранной датой.
При выборе даты соседние дни открываются сдвигом, остальные — через плавное
исчезновение и появление содержимого без пролистывания промежуточных дней.
Если выбранный день ещё загружается, экран остаётся пустым; материал или ошибка
появляются фэйдом после завершения загрузки. Лампада загрузки на «Домой» не показывается.
Нажатие на название месяца открывает нижнюю панель календаря с выбором даты;
месяцы переключаются страницами через PageView, свайпом или стрелками.
Панель заранее резервирует шесть строк недель, чтобы не прыгать при смене месяца. Селектор месяца расположен слева,
кнопка «Вернуться» справа возвращает к текущему дню.
Выбранная дата отмечена заливкой, сегодняшняя — кольцом, дни с активностью — огоньком.

## Архитектура

Используем feature-first и строгую Clean Architecture:

```text
presentation → domain ← data
```

- Каждая фича находится в `lib/features/<feature>/` и содержит `domain`,
  `data` и `presentation`. В `lib/core/` попадает только общий код.
- `domain` — чистый Dart: без Flutter, data- и presentation-импортов.
- `data` не импортирует presentation. DTO остаются в data-слое и переходят в
  entity через отдельный mapper.
- UI вызывает use case, не репозиторий. Репозиторий преобразует исключения
  data-слоя в `AppFailure`; границу пересекает `Result<T>`.
- Провайдеры Riverpod находятся в `presentation/providers/`; единственный
  допустимый импорт data из presentation — composition root фичи.
- Entity — `freezed` без JSON, DTO — `freezed` с `fromJson`.

Доменные правила покрываются unit-тестами рядом с use case, UI — widget-тестами
в зеркальной структуре `test/`.

## Иконки интерфейса

Боковые поля экранов — 16 логических пикселей, заданы в `AppSpacing`
через расширение глобальной темы. Списки, справки и читалки используют эти
поля. У материалов дня на главной собственные боковые поля — 20 пикселей
(`AppSpacing.dayEntryInset`). Две галочки находятся внутри строки заголовка: приглушённые у непрочитанного
материала и акцентные у прочитанного. Место под них сохраняется в обоих
состояниях; основной текст всегда начинается на линии 20 пикселей. В читалках слева оставлено ещё
13 пикселей под панель прогресса. Поля кликабельных строк находятся внутри
кнопки, чтобы ink расходился на всю ширину экрана. Внутренние отступы
компонентов и расположение управляющих панелей читалки задаются отдельно.

Все управляющие иконки — из `CupertinoIcons`. Контурные варианты используются
для обычного состояния, залитые — для выбранных вкладок и сохранённых закладок.
Кнопка назад везде использует `CupertinoIcons.arrow_left` размером 22 логических
пикселя; автоматические кнопки AppBar настроены в обеих темах `AppTheme`.
Полный текст открывается через `CupertinoIcons.fullscreen`, справка — через
`CupertinoIcons.info`, раскрытие — через `chevron_up` / `chevron_down`.
Фирменная лампада и иконки запуска приложения используют собственные ассеты.

## Локальная разработка

Для iOS требуется Flutter 3.44 или новее. Если Swift Package Manager отключён:

```sh
flutter config --enable-swift-package-manager
```

После изменения Dart-кода выполните:

```sh
dart format .
flutter analyze
flutter test
```

После изменения `freezed`-entity или JSON DTO сначала запустите:

```sh
dart run build_runner build --delete-conflicting-outputs
```

## Контент и локальное состояние

День загружается с `azbyka.ru/days/{дата}`. Кэш привязан к запрошенной дате;
данные за другую дату не подставляются. У загрузки общий бюджет 10 секунд, до
трёх попыток и без повторов при ошибке парсинга. Логи сети доступны только в
debug-сборке.

`SharedPreferences` хранит дневной прогресс, посещённые дни, закладки, главы
Библии и личный прогресс курса. Толкования и рассказы дня загружаются лениво.
Напоминания планируются на неделю вперёд и только для непрочитанных разделов.

Известные ограничения:

- маркеры постов и праздников в недельной полоске пока не выводятся;
- серия дней уже считается, но в интерфейсе не показана;
- кэш чтения пока не ограничен по размеру;
- уведомления Android требуют отдельной проверки `POST_NOTIFICATIONS`.

## Нативная часть и ассеты

В release-варианте Android нужно разрешение `android.permission.INTERNET` в
`android/app/src/main/AndroidManifest.xml`: debug/profile-манифесты release не
покрывают.

Иконка использует два исходника:

- `assets/icon/icon_foreground.png` — прозрачный foreground Android adaptive icon;
- `assets/icon/icon_ios.png` — непрозрачная подложка iOS.

Перед обновлением iOS-версии запустите
`dart run tool/make_ios_icon.dart`, затем `dart run flutter_launcher_icons`.
Скрипт композитит прозрачный Android-исходник на фон: одного
`remove_alpha_ios` недостаточно, поскольку генератор не очищает RGB в
прозрачных пикселях. После генерации проверьте, что
`ASSETCATALOG_COMPILER_GENERATE_SWIFT_ASSET_SYMBOL_EXTENSIONS` в
`ios/Runner.xcodeproj/project.pbxproj` остаётся `YES`.

После изменения Android/iOS-конфигурации, splash-экрана или иконок вручную
проверьте Android release/profile и iOS release: холодный старт в светлой и
тёмной теме, сеть и отрисовку иконки.
